# 第1回　暗号技術の基礎と安全性の考え方

この記事は、暗号技術の基礎を体系的に学ぶ連載記事の第1回です。現代社会のあらゆる場面で使われている暗号技術について、その目的・仕組み・安全性の考え方を整理し、後続の記事で学ぶ具体的な暗号技術の理解の土台を作ります。暗号理論のアルゴリズムだけでなく、必要な安全性を暗号理論でどのようにモデル化して評価しているかは、暗号理論における重要なポイントの一つになります。

## 1.1 はじめに：なぜ暗号が必要か

インターネットが普及し、ディジタル情報が日々やり取りされる現代社会において、 **情報の保護** は不可欠な技術要素となっています。オンラインバンキング、メッセージアプリ、クラウドストレージ、電子商取引など、私たちが日常的に使うサービスの背後には必ず暗号技術があります。

しかし、暗号は単に「秘密を隠す」だけではありません。現代暗号学では、情報セキュリティの4つの基本目的を達成するための技術として位置づけられています：

### 1. 機密性（Confidentiality）
データが許可されていない第三者に読まれないようにすること。メッセージや文書の内容を暗号化により隠蔽します。

### 2. 完全性（Integrity）
データが改ざんされていないことを確認できること。送信者が送ったデータと受信者が受け取ったデータが同一であることを保証します。


### 3. 認証（Authentication）
通信相手やデータの送信者が本物であることを確認すること。なりすましを防ぐ重要な機能です。

### 4. 否認防止（Non-repudiation）
データの送信者が「自分が送った」ことを後から否定できないようにすること。ディジタル署名により実現されます。

### 情報セキュリティの基本目的と関連技術

以下のテーブルは、情報セキュリティの4つの基本目的と、それぞれを実現するために使用される主要な暗号技術の関係を示しています：

| 基本目的     | 定義                                                                   | 実現する暗号技術                                                        | 具体的な用途例                                         |
| ------------ | ---------------------------------------------------------------------- | ----------------------------------------------------------------------- | ------------------------------------------------------ |
| **機密性**   | データが許可されていない第三者に読まれないようにすること               | 共通鍵暗号（AES、DES）<br>公開鍵暗号（RSA、ECC）<br>ハイブリッド暗号    | HTTPS通信<br>メール暗号化<br>ファイル暗号化            |
| **完全性**   | データが改ざんされていないことを確認できること                         | ハッシュ関数（SHA-256）<br>メッセージ認証符号（HMAC）<br>ディジタル署名 | ソフトウェア配布<br>ファイル転送<br>データベース整合性 |
| **認証**     | 通信相手やデータの送信者が本物であることを確認すること                 | ディジタル署名<br>ディジタル証明書<br>認証プロトコル                    | Webサイト認証<br>ユーザー認証<br>デバイス認証          |
| **否認防止** | データの送信者が「自分が送った」ことを後から否定できないようにすること | ディジタル署名<br>タイムスタンプ<br>監査ログ                            | 電子契約<br>金融取引<br>法的文書                       |

このテーブルからわかるように、現代の暗号技術は単一の目的を達成するだけでなく、複数の技術を組み合わせることで包括的な情報セキュリティを実現しています。特に、ディジタル署名は認証、完全性、否認防止の3つの目的を同時に満たす重要な技術となっています。


## 1.2 現代暗号の分類

現代暗号技術は、その目的と仕組みに応じていくつかの種類に分類できます。以下に主要な分類を示します：

### 1. 共通鍵暗号（Symmetric-key encryption）
送信者と受信者が同じ秘密鍵を事前に共有し、この鍵でデータを暗号化・復号する方式です。暗号化・復号の処理が高速で、大容量のデータ処理に適している反面、送信者と受信者の間で事前に秘密鍵の共有が必要なため、鍵の安全な配布が課題となります。また、機密性を担保したい送信者と受信者の組み合わせごとに個別の鍵を生成する必要があります。

**特徴** ：暗号化と復号に同一の鍵を使用  
**用途** ：大量データの高速暗号化  
**代表例** ：AES、DES  
**身近な例** ：Wi-Fiの暗号化、ハードディスクの暗号化

```
送信者 ---[鍵K]---> 暗号化 ---> 暗号文 ---> 復号 ---[鍵K]---> 受信者
```

### 2. 公開鍵暗号（Asymmetric-key encryption）
数学的に関連する2つの鍵（公開鍵と秘密鍵）のペアを使用する暗号方式です。公開鍵は誰でもアクセス可能で、秘密鍵は所有者のみが管理します。鍵配布に対する問題を解決できる一方、処理速度が共通鍵暗号より遅いという特徴があります。

**特徴** ：暗号化と復号に異なる鍵（公開鍵・秘密鍵）を使用  
**用途** ：鍵交換、小さなデータの暗号化、ディジタル署名の基盤  
**代表例** ：RSA、ElGamal、楕円曲線暗号（ECC）  
**身近な例** ：HTTPS通信の初期段階、メール暗号化（PGP）

```
送信者 ---[公開鍵]---> 暗号化 ---> 暗号文 ---> 復号 ---[秘密鍵]---> 受信者
```

### 3. ディジタル署名（Digital signature）
データの送信者が自分の秘密鍵で「署名」を生成し、受信者が対応する公開鍵で署名を検証する仕組みです。手書きの署名と同様に、データの作成者の証明と改ざん検知を同時に実現します。

**特徴** ：データの作成者を証明し、改ざんを検知  
**用途** ：認証、完全性確認、否認防止  
**代表例** ：RSA署名、DSA、ECDSA  
**身近な例** ：ソフトウェアの配布署名、電子契約、SSL証明書

### 4. ハッシュ関数（Hash function）
どんなサイズの入力データでも、固定長のハッシュ値（「データの指紋」のようなもの）を生成する一方向関数です。元のデータにわずかな変更があっても、まったく異なるハッシュ値が生成されるため、データの完全性確認に使われます。

**特徴** ：任意長データを固定長の値（ハッシュ値）に変換  
**用途** ：データの完全性確認、ディジタル署名との組み合わせ、パスワード保存  
**代表例** ：SHA-256、SHA-3、MD5（非推奨）  
**身近な例** ：ファイルのダウンロード確認、Gitのコミット管理、パスワード認証

### 5. 秘密分散（Secret sharing）
1つの秘密情報（鍵やパスワードなど）を複数の断片（シェア）に分割し、一定数以上の断片が揃わないと元の秘密を復元できないようにする技術です。単一障害点を回避し、セキュリティと可用性を両立できます。

**特徴** ：秘密情報を複数の断片に分割して保管  
**用途** ：重要な鍵の管理、冗長性確保、リスク分散  
**代表例** ：Shamir秘密分散、しきい値暗号  
**身近な例** ：銀行の金庫（複数の鍵が必要）、仮想通貨ウォレットのマルチシグ

### 複数の暗号技術の利用

これらの暗号技術は、単独で使われることもあれば、組み合わせて使われることもあります。例えば、TLS/HTTPSでは公開鍵暗号・共通鍵暗号・ハッシュ関数・ディジタル署名が組み合わせられて動作します。

## 1.3 安全性モデルの概要

暗号が「安全である」とはどういうことでしょうか？暗号学では、安全性を厳密に定義するため、 **安全性モデル** という概念を使います。

安全性モデルでは、 **攻撃者の能力** （どのような攻撃を想定するか）と **安全性の目標** （何を達成したいか）を組み合わせて、暗号の安全性を評価します。以下では、暗号、ディジタル署名、ハッシュ関数の3つの分野に分けて、それぞれの安全性モデルを詳しく説明します。

## 1.3.1 暗号における安全性モデル

### 攻撃者の能力（攻撃モデル）

暗号に対する攻撃者の能力を段階的にモデル化します。

#### 1. COA（Ciphertext-Only Attack：暗号文単独攻撃）
攻撃者は暗号文しか入手できない最も基本的な攻撃モデルです。古典暗号の解読でよく想定されました。現代の暗号技術では原理的にこの攻撃に対する耐性を有しており、ほとんど議論されません。ただし、運用方法に問題がある場合などにこの攻撃を許す発生することがあります。

古典暗号では、シーザー暗号のような文字の置き換えによる暗号化において、統計的に出現しやすい文字と暗号文における文字の出現頻度を調べることで、暗号文単独攻撃を許してしまう攻撃が知られています。

**例** ：ネットワーク上で暗号化された通信を傍受したが、平文は不明な状況

#### 2. KPA（Known-Plaintext Attack：既知平文攻撃）
攻撃者はいくつかの平文と対応する暗号文のペアを知っている状態です。第二次世界大戦中のエニグマ暗号の解読で使われた攻撃モデルです。現代暗号技術においては以降のより強い攻撃での議論が主であり、ほとんど議論されません。

**例** ：標準的なメッセージ（「こんにちは」「ありがとう」など）とその暗号文のペアを複数収集

#### 3. CPA（Chosen-Plaintext Attack：選択平文攻撃）
攻撃者が任意の平文を暗号化させることができる攻撃モデルです。公開鍵暗号では誰でも公開鍵で暗号化できるため、この攻撃は常に可能となります。ちなみに、問い合わせることで特定の出力結果を得ることができるものを「オラクル」と呼び、暗号化であれば「暗号化オラクル」、復号であれば「復号オラクル」と呼びます。

```
攻撃者 ---> 任意の平文選択 ---> 暗号化オラクル ---> 暗号文を観察
```

**例** ：公開鍵暗号で、攻撃者が任意のメッセージを暗号化して暗号文のパターンを分析

#### 4. CCA1（Non-adaptive Chosen-Ciphertext Attack：非適応的選択暗号文攻撃）
攻撃者が任意の暗号文を復号させることができるが、解読対象の暗号文を受け取る **前** のみに限定される攻撃モデルです。「ランチタイム攻撃」とも呼ばれます。

**例** ：暗号化サーバーに任意の暗号文を送信して復号結果を観察（解読対象の暗号文取得前）

#### 5. CCA2（Adaptive Chosen-Ciphertext Attack：適応的選択暗号文攻撃）
攻撃者が解読対象の暗号文を受け取った **後** も、任意の暗号文を復号させることができる最も強力な攻撃モデルです。実際のネットワーク攻撃に近い状況をモデル化しています。

**例** ：解読対象の暗号文を取得した後も、復号オラクルにアクセスして攻撃を継続

#### 攻撃の強さ

攻撃の強さは、以下の順に強くなります。

$COA < KPA < CPA < CCA1 < CCA2$

### 暗号における安全性の目標

暗号が達成すべき安全性の目標を段階的に定義します：

#### 1. OW（One-Wayness：一方向性）
攻撃者が暗号文から元の平文を復元できない性質です。最も基本的な安全性要件です。

**定義** ：
任意の効率的な攻撃者に対して、暗号文から対応する平文を計算的に求めることが困難である

**OW攻撃ゲーム** ：
1. チャレンジャーが鍵生成アルゴリズム $\text{Gen}(1^n)$ （nの鍵長をもつ鍵生成）を実行
2. チャレンジャーがランダムな平文 $m$ を選択し、暗号化 $c = \text{Enc}_{pk}(m)$ を実行
3. 攻撃者に公開鍵 $pk$ と暗号文 $c$ を送信
4. 攻撃者が平文 $m'$ を推測
5. 攻撃成功の条件：$m' = m$

**数学的定義** ：
暗号 $\Pi = (\text{Gen}, \text{Enc}, \text{Dec})$ が一方向性の安全性をもつということは、任意の攻撃者 $\mathcal{A}$ に対して、以下の不等式が成り立つことです：

$$\Pr[\text{OW}_{\mathcal{A},\Pi}(n) = 1] \leq \text{negl}(n)$$

ここで：
- $\text{OW}_{\mathcal{A},\Pi}(n)$ は攻撃者 $\mathcal{A}$ と暗号 $\Pi$ の間のOW攻撃ゲームが成功するかどうか（1なら成功、0なら失敗）
- $\text{negl}(n)$ は negligible な関数（後述）
- $n$ はセキュリティパラメータ（通常は鍵長）

**Negligible関数の定義** ：
関数 $f: \mathbb{N} \rightarrow \mathbb{R}_{>0} $ が negligible （無視できる大きさ）であるとは、任意の多項式 $p(n)$ に対して、十分大きな $n$ について以下が成り立つことです：

$$f(n) < \frac{1}{p(n)}$$

つまり、negligibleな関数は任意の多項式よりも急速に0に収束します。

**例** ：
- $f(n) = 2^{-n}$ は negligible（指数関数的に減少）
- $f(n) = n^{-100}$ は negligible（多項式よりも急速に減少）
- $f(n) = n^{-1}$ は negligible ではない（多項式と同じオーダー）

**OW安全性の直感的理解** ：
OW安全な暗号では、攻撃者が暗号文から元の平文を復元する確率が negligible です。つまり、攻撃者は実質的に暗号文から平文を推測することができません。

**計算複雑性との関係** ：
攻撃者の計算時間が多項式時間の場合、成功確率は negligible でなければなりません。これにより、OW安全性が計算困難性に基づくことが保証されます。RSA暗号の基盤である素因数分解問題や、ElGamal暗号や楕円曲線暗号の基盤である離散対数問題などの計算困難性仮定（セキュリティパラメータに対する多項式時間では解けないということ）に依存します。

**OW安全性の限界** ：
OW安全性は最も基本的な安全性要件です。暗号文の部分的な情報漏洩は防げません。現代暗号では通常、より強いIND安全性を要求しますが、前述の通り、現代暗号技術における計算困難性の評価に対応するため、暗号理論において重要な安全性の一つとなります。

#### 2. IND（Indistinguishability：識別不可能性）
攻撃者が2つの異なる平文から生成された暗号文を区別できない性質です。現代暗号における標準的な秘匿性の定義となっています。

**定義** ：
任意の効率的な攻撃者に対して、2つの異なる平文の暗号文を区別することが計算的に困難である

**IND攻撃ゲーム** ：
1. チャレンジャーが鍵生成アルゴリズム $\text{Gen}(1^n)$ を実行
2. 攻撃者が同じ長さの2つの平文 $m_0, m_1$ を選択
3. チャレンジャーがランダムビット $b \leftarrow \{0,1\}$ を選択
4. チャレンジャーが $c = \text{Enc}_{pk}(m_b)$ を計算して攻撃者に送信
5. 攻撃者がビット $b'$ を推測
6. 攻撃成功の条件：$b' = b$

**数学的定義** ：
暗号 $\Pi = (\text{Gen}, \text{Enc}, \text{Dec})$ が識別不可能性の安全性をもつということは、任意の攻撃者 $\mathcal{A}$ に対して、以下の不等式が成り立つことです：

$$\Pr[\text{IND}_{\mathcal{A},\Pi}(n) = 1] - \frac{1}{2} \leq \text{negl}(n)$$

ここで：
- $\text{IND}_{\mathcal{A},\Pi}(n)$ は攻撃者 $\mathcal{A}$ と暗号 $\Pi$ の間のIND攻撃ゲームが成功するかどうか（1なら成功、0なら失敗）
- $\frac{1}{2}$ は当てずっぽうの確率（50%）
- $\text{negl}(n)$ は negligible な関数

**IND安全性の直感的理解** ：
IND安全な暗号では、攻撃者が2つの平文の暗号文を区別する確率が当てずっぽう（50%）より有意に高くなりません。つまり、暗号文からは元の平文に関する情報が一切漏洩しません。

**OW安全性との関係** ：
IND安全性はOW安全性より強い安全性定義です。IND安全な暗号は自動的にOW安全ですが、逆は成り立ちません。現代暗号では通常、IND安全性を要求します。


#### 3. NM（Non-Malleability：非展性）
攻撃者が暗号文を改変して、元の平文と関連性のある別の平文に対応する有効な暗号文を作成できない性質です。

**定義** ：
任意の効率的な攻撃者に対して、与えられた暗号文を改変して、元の平文と関連性のある別の平文に対応する有効な暗号文を作成することが計算的に困難である

**NM攻撃ゲーム** ：
1. チャレンジャーが鍵生成アルゴリズム $\text{Gen}(1^n)$ を実行
2. 攻撃者が平文 $m$ を選択
3. チャレンジャーが $c = \text{Enc}_{pk}(m)$ を計算して攻撃者に送信
4. 攻撃者が暗号文 $c'$ を出力（$c' \neq c$）
5. 攻撃者が関係 $R$ を出力（後述で補足）
6. 攻撃成功の条件：$c'$ が有効な暗号文で、かつ $R(m, \text{Dec}_{sk}(c')) = 1$

**関係 $R$ について** ：
関係 $R$ は、元の平文 $m$ と改変された暗号文を復号した平文 $m' = \text{Dec}_{sk}(c')$ の間に意味的な関連性があるかどうかを判定する関数です。攻撃者が事前に定義し、攻撃の目標を明確にします。

**関係 $R$ の具体例** ：
- **等号関係** ：$R(m, m') = 1$ ならば $m = m'$ （完全なコピー攻撃）
- **加算関係** ：$R(m, m') = 1$ ならば $m' = m + 1$ （送金額を1円増やす攻撃）
- **乗算関係** ：$R(m, m') = 1$ ならば $m' = 2 \times m$ （送金額を2倍にする攻撃）
- **ビット反転関係** ：$R(m, m') = 1$ ならば $m'$ は $m$ の特定ビットが反転したもの
- **部分文字列関係** ：$R(m, m') = 1$ ならば $m'$ は $m$ の部分文字列を含む

**攻撃成功の意味** ：
攻撃が成功するとは、攻撃者が元の暗号文 $c$ を改変して新しい暗号文 $c'$ を作成し、その復号結果 $m'$ が元の平文 $m$ と攻撃者が定義した関係 $R$ を満たすことを意味します。つまり、攻撃者は暗号文の改変を通じて、元の平文と意味的に関連のある別の平文を「作り出す」ことができてしまいます。

**数学的定義** ：
暗号 $\Pi = (\text{Gen}, \text{Enc}, \text{Dec})$ が非展性の安全性をもつということは、任意の攻撃者 $\mathcal{A}$ に対して、以下の不等式が成り立つことです：

$$\Pr[\text{NM}_{\mathcal{A},\Pi}(n) = 1] \leq \text{negl}(n)$$

ここで：
- $\text{NM}_{\mathcal{A},\Pi}(n)$ は攻撃者 $\mathcal{A}$ と暗号 $\Pi$ の間のNM攻撃ゲームが成功するかどうか（1なら成功、0なら失敗）
- $\text{negl}(n)$ は negligible な関数

**NM安全性の直感的理解** ：
NM安全な暗号では、攻撃者が暗号文を改変して、元の平文と意味的に関連のある別の平文の暗号文を作成することができません。例えば、送金額「1000円」の暗号文を「9000円」の暗号文に書き換えるような攻撃を防ぎます。

**IND安全性との関係** ：
NM安全性はIND安全性とは独立した概念です。IND安全な暗号が必ずしもNM安全とは限らず、逆も同様です。しかし、IND-CCA2安全な暗号は自動的にNM安全であることが証明されています。

**実用的な重要性** ：
電子投票システムや電子マネーなど、暗号文の改変が重大な問題を引き起こす可能性があるシステムでは、NM安全性が特に重要です。

**例** ：送金額「1000円」の暗号文を「9000円」の暗号文に書き換えるような攻撃を防ぐ

### 暗号における組み合わせ安全性定義

#### IND-CPA（識別不可能性・選択平文攻撃耐性）
公開鍵暗号の基本的な安全基準です。攻撃者が任意の平文を暗号化できる状況でも、2つの平文の暗号文を区別できません。

**IND-CPA攻撃ゲームの詳細** ：

1. **初期化段階** ：
   - チャレンジャーが鍵生成アルゴリズム $\text{Gen}(1^n)$ を実行
   - 公開鍵 $pk$ を攻撃者 $\mathcal{A}$ に送信

2. **学習段階** ：
   - 攻撃者 $\mathcal{A}$ が暗号化オラクル $\text{Enc}_{pk}(\cdot)$ に任意の平文を送信
   - オラクルが対応する暗号文を返す
   - この段階は任意の回数実行可能

3. **チャレンジ段階** ：
   - 攻撃者 $\mathcal{A}$ が同じ長さの2つの平文 $m_0, m_1$ を選択
   - チャレンジャーがランダムビット $b \leftarrow \{0,1\}$ を選択
   - チャレンジャーが $c^* = \text{Enc}_{pk}(m_b)$ を計算して攻撃者に送信

4. **推測段階** ：
   - 攻撃者 $\mathcal{A}$ がビット $b'$ を推測
   - 攻撃成功の条件：$b' = b$

**成功確率の定義** ：

$$
\text{Adv}\_{\mathcal{A},\Pi}^{\text{IND-CPA}}(n) = \left| \Pr[\text{IND-CPA}_{\mathcal{A},\Pi}(n) = 1] - \frac{1}{2} \right|
$$

**安全性の定義** ：
暗号スキーム $\Pi$ がIND-CPA安全であるとは、任意の効率的な攻撃者 $\mathcal{A}$ に対して：
$$\text{Adv}_{\mathcal{A},\Pi}^{\text{IND-CPA}}(n) \leq \text{negl}(n)$$

```
攻撃者 ---> 平文選択 ---> 暗号化オラクル ---> 暗号文
   ↑                                        |
   |-- チャレンジ暗号文を受け取り判別 --------|
```

#### IND-CCA2（識別不可能性・適応的選択暗号文攻撃耐性）
現代暗号の **ゴールドスタンダード** とされる最も強い安全性です。攻撃者が復号オラクルにアクセスできる状況でも安全性を保ちます。

**IND-CCA2攻撃ゲームの詳細** ：

1. **初期化段階** ：
   - チャレンジャーが鍵生成アルゴリズム $\text{Gen}(1^n)$ を実行
   - 公開鍵 $pk$ を攻撃者 $\mathcal{A}$ に送信

2. **学習段階** ：
   - 攻撃者 $\mathcal{A}$ が暗号化オラクル $\text{Enc}\_{pk}(\cdot)$ と復号オラクル $\text{Dec}\_{sk}(\cdot)$ にアクセス可能
   - 任意の平文の暗号化と任意の暗号文の復号が可能
   - この段階は任意の回数実行可能

3. **チャレンジ段階** ：
   - 攻撃者 $\mathcal{A}$ が同じ長さの2つの平文 $m_0, m_1$ を選択
   - チャレンジャーがランダムビット $b \leftarrow \{0,1\}$ を選択
   - チャレンジャーが $c^* = \text{Enc}_{pk}(m_b)$ を計算して攻撃者に送信

4. **推測段階** ：
   - 攻撃者 $\mathcal{A}$ が復号オラクルにアクセス可能（ただし $c^*$ の復号は禁止）
   - 攻撃者 $\mathcal{A}$ がビット $b'$ を推測
   - 攻撃成功の条件：$b' = b$

**IND-CCA2とIND-CPAの違い** ：
- IND-CPA：チャレンジ段階後に復号オラクルにアクセス不可
- IND-CCA2：チャレンジ段階後も復号オラクルにアクセス可能（$c^*$ を除く）

**成功確率の定義** ：
$$\text{Adv}\_{\mathcal{A},\Pi}^{\text{IND-CCA2}}(n) = \left| \Pr[\text{IND-CCA2}_{\mathcal{A},\Pi}(n) = 1] - \frac{1}{2} \right|$$

**安全性の定義** ：
暗号スキーム $\Pi$ がIND-CCA2安全であるとは、任意の効率的な攻撃者 $\mathcal{A}$ に対して：
$$\text{Adv}_{\mathcal{A},\Pi}^{\text{IND-CCA2}}(n) \leq \text{negl}(n)$$

**実用例** ：SSL/TLSの古いバージョンに存在したパディングオラクル攻撃では、攻撃者が暗号文を改変してサーバーに送信し、エラーメッセージの違いから通信内容を解読できてしまいました。IND-CCA2安全な暗号ではこのような攻撃を防げます。

## 1.3.2 ディジタル署名における安全性モデル

### 署名に対する攻撃モデル

#### 1. KMA（Known Message Attack：既知メッセージ攻撃）
攻撃者はいくつかのメッセージとその署名のペアを知っている状態です。

**攻撃シナリオ** ：
- 攻撃者は公開された文書やメッセージとその署名を収集
- 例：ウェブサイトの証明書、ソフトウェアの署名、公開された文書の署名など
- 攻撃者はこれらの情報から署名アルゴリズムの弱点を探る

**現実的な例** ：
攻撃者が収集した情報：
- メッセージ1: "Hello World" → 署名: $\sigma_1$
- メッセージ2: "Digital Signature" → 署名: $\sigma_2$
- メッセージ3: "Cryptography" → 署名: $\sigma_3$


#### 2. CMA（Chosen Message Attack：選択メッセージ攻撃）
攻撃者が任意のメッセージの署名を取得できる攻撃モデルです。最も現実的な攻撃モデルです。

**攻撃シナリオ** ：
- 攻撃者は署名オラクル（署名生成サービス）にアクセス可能
- 任意のメッセージを選択して署名を取得
- 取得した署名から秘密鍵の情報を推測

**攻撃フロー** ：
```
攻撃者 ---> 任意のメッセージ選択 ---> 署名オラクル ---> 署名を観察
```

**具体的な攻撃例** ：
1. **線形関係攻撃** ：メッセージ間に線形関係がある場合の攻撃
2. **ハッシュ関数の弱点利用** ：ハッシュ関数の衝突を利用した攻撃
3. **楕円曲線の特性利用** ：楕円曲線の数学的性質を利用した攻撃

### 署名における安全性の目標

#### 1. EUF（Existential Unforgeability：存在偽造困難性）
攻撃者が新しいメッセージに対する有効な署名を作成できない性質です。

**定義** ：
任意の効率的な攻撃者Aに対して、以下の確率が negligible である：
$$\Pr[(m^\*, \sigma^\*) \leftarrow A^{\text{Sign}(\cdot)}(\text{pk}) : \text{Verify}(\text{pk}, m^\*, \sigma^\*) = 1 \land m^\* \notin Q]$$
ここで、Qは署名オラクルに送信されたメッセージの集合です。

**攻撃の種類** ：
- **完全偽造** ：全く新しいメッセージに対する署名の作成
- **選択的偽造** ：特定のメッセージに対する署名の作成

#### 2. SUF（Strong Unforgeability：強偽造困難性）
攻撃者が既知のメッセージ・署名ペアを改変した署名を作成できない性質です。

**定義** ：
任意の効率的な攻撃者Aに対して、以下の確率が negligible である：
$$\Pr[(m^\*, \sigma^\*) \leftarrow A^{\text{Sign}(\cdot)}(\text{pk}) : \text{Verify}(\text{pk}, m^\*, \sigma^\*) = 1 \land (m^\*, \sigma^\*) \notin Q]$$
ここで、Qは署名オラクルから取得したメッセージ・署名ペアの集合です。

**攻撃の種類** ：
- **署名の再利用** ：既存の署名を別のメッセージに適用
- **署名の改変** ：既存の署名を数学的に操作して新しい署名を作成

### 署名における組み合わせ安全性定義

#### EUF-CMA（存在偽造困難性・選択メッセージ攻撃耐性）
ディジタル署名における標準的な安全性モデルで、攻撃者が任意のメッセージの署名を取得できる状況でも、新しいメッセージに対する有効な署名を作成できないことを保証します。

**攻撃ゲーム** ：
1. **初期化フェーズ** ：署名者と攻撃者が公開パラメータを共有
2. **クエリフェーズ** ：攻撃者が署名オラクルに任意のメッセージを送信して署名を取得
3. **出力フェーズ** ：攻撃者が新しいメッセージとその署名のペアを出力
4. **検証フェーズ** ：出力されたメッセージが署名オラクルに送信されていなければ攻撃成功

**具体的な攻撃例** ：
- **RSA署名の攻撃** ：小さな指数eを使用した場合の攻撃
- **DSA署名の攻撃** ：乱数生成の弱点を利用した攻撃
- **楕円曲線署名の攻撃** ：曲線の位数が小さな素因数を持つ場合の攻撃

#### SUF-CMA（強偽造困難性・選択メッセージ攻撃耐性）
より強い安全性で、既知のメッセージ・署名ペアの改変も防ぎます。

**追加の攻撃例** ：
- **署名の再利用攻撃** ：既存の署名を別のコンテキストで使用
- **署名の合成攻撃** ：複数の署名を組み合わせて新しい署名を作成
- **タイムスタンプ攻撃** ：署名のタイムスタンプを改変する攻撃

## 1.3.3 ハッシュ関数における安全性モデル

### ハッシュ関数に対する攻撃モデル

#### 1. 原像攻撃（Preimage Attack）
攻撃者が与えられたハッシュ値に対応する入力を見つける攻撃です。

**攻撃シナリオ** ：
- 攻撃者は特定のハッシュ値$y$が与えられる
- 攻撃者は$H(x) = y$を満たす入力$x$を見つける必要がある
- 最も基本的な攻撃モデル

**数学的定義** ：
与えられた $y \in \{0,1\}^n$ に対して、$H(x) = y$ を満たす $x \in \{0,1\}^*$ を見つける

**攻撃手法** ：
1. **ブルートフォース攻撃** ：全ての可能な入力を試行
   - 計算量：$O(2^n)$ （nはハッシュ値のビット長）
2. **誕生日攻撃の応用** ：ランダムな入力を生成してハッシュ値を計算
3. **数学的弱点の利用** ：ハッシュ関数の数学的構造を利用

**現実的な例** ：
攻撃者が知っている情報：
- ハッシュ値: `5d41402abc4b2a76b9719d911017c592`
- 目標: このハッシュ値を生成する入力を見つける

#### 2. 第二原像攻撃（Second Preimage Attack）
攻撃者が与えられた入力と異なる入力で、同じハッシュ値を生成する攻撃です。

**攻撃シナリオ** ：
- 攻撃者は特定の入力$x_1$が与えられる
- 攻撃者は$x_1 \neq x_2$かつ$H(x_1) = H(x_2)$を満たす$x_2$を見つける必要がある
- 原像攻撃より制約が強い

**数学的定義** ：
与えられた $x_1 \in \{0,1\}^*$ に対して、$x_1 \neq x_2$ かつ $H(x_1) = H(x_2)$ を満たす $x_2 \in \{0,1\}^*$ を見つける

**攻撃手法** ：
1. **誕生日攻撃** ：$O(2^{n/2})$の計算量で攻撃可能
2. **差分攻撃** ：入力の差分パターンを利用
3. **構造的攻撃** ：ハッシュ関数の内部構造を利用

**現実的な例** ：
攻撃者が知っている情報：
- 元の文書: `"Hello World"`
- 目標: `"Hello World"`と異なるが同じハッシュ値を生成する文書を見つける

#### 3. 衝突攻撃（Collision Attack）
攻撃者が異なる2つの入力で同じハッシュ値を生成する攻撃です。

**攻撃シナリオ** ：
- 攻撃者は任意の2つの異なる入力$x_1, x_2$を見つける
- $H(x_1) = H(x_2)$かつ$x_1 \neq x_2$を満たす必要がある
- 最も制約が緩い攻撃モデル

**数学的定義** ：
$H(x_1) = H(x_2)$ かつ $x_1 \neq x_2$ を満たす $x_1, x_2 \in \{0,1\}^*$ を見つける

**攻撃手法** ：
1. **誕生日攻撃** ：$O(2^{n/2})$の計算量で攻撃可能
2. **MD構造の攻撃** ：Merkle-Damgård構造の弱点を利用
3. **差分解析** ：入力の差分パターンを系統的に探索

**現実的な例** ：
攻撃者の目標：
- 異なる2つの文書で同じハッシュ値を生成
- 例：正規のソフトウェアとマルウェアで同じハッシュ値

### ハッシュ関数における安全性の目標

#### 1. 一方向性（One-Wayness）
与えられたハッシュ値から元の入力を計算的に求めることが困難な性質です。

**定義** ：
任意の効率的な攻撃者Aに対して、以下の確率が negligible である：
$$\Pr[y \leftarrow \{0,1\}^n; x \leftarrow A(y) : H(x) = y]$$

**重要性** ：
- パスワードの安全な保存
- デジタル署名の基盤
- 認証システムの安全性

#### 2. 第二原像耐性（Second Preimage Resistance）
与えられた入力と異なる入力で同じハッシュ値を生成することが困難な性質です。

**定義** ：
任意の効率的な攻撃者Aに対して、以下の確率が negligible である：
$$\Pr[x_1 \leftarrow \{0,1\}^*; x_2 \leftarrow A(x_1) : x_1 \neq x_2 \land H(x_1) = H(x_2)]$$

**重要性** ：
- 文書の完全性保証
- デジタル署名の安全性
- データの改ざん検出

#### 3. 衝突耐性（Collision Resistance）
異なる2つの入力で同じハッシュ値を生成することが困難な性質です。

**定義** ：
任意の効率的な攻撃者Aに対して、以下の確率が negligible である：
$$\Pr[(x_1, x_2) \leftarrow A : x_1 \neq x_2 \land H(x_1) = H(x_2)]$$

**重要性** ：
- デジタル証明書の安全性
- ブロックチェーンの整合性
- ソフトウェアの完全性検証

### ハッシュ関数における安全性定義

#### OW（一方向性）
任意の効率的な攻撃者に対して、ハッシュ値から対応する入力を計算的に求めることが困難

**攻撃ゲーム** ：
1. **初期化** ：ハッシュ関数Hが公開される
2. **挑戦** ：ランダムなハッシュ値yが生成される
3. **攻撃** ：攻撃者がyに対応する入力xを見つける
4. **検証** ：H(x) = yであれば攻撃成功

#### SPR（第二原像耐性）
任意の効率的な攻撃者に対して、与えられた入力と異なる入力で同じハッシュ値を生成することが困難

**攻撃ゲーム** ：
1. **初期化** ：ハッシュ関数Hが公開される
2. **挑戦** ：ランダムな入力x₁が生成される
3. **攻撃** ：攻撃者がx₁ ≠ x₂かつH(x₁) = H(x₂)を満たすx₂を見つける
4. **検証** ：条件を満たせば攻撃成功

#### CR（衝突耐性）
任意の効率的な攻撃者に対して、異なる2つの入力で同じハッシュ値を生成することが困難

**攻撃ゲーム** ：
1. **初期化** ：ハッシュ関数Hが公開される
2. **攻撃** ：攻撃者がx₁ ≠ x₂かつH(x₁) = H(x₂)を満たすペアを見つける
3. **検証** ：条件を満たせば攻撃成功

**安全性の強さ** ：
$OW < SPR < CR$

**証明の概要** ：
- CR ⇒ SPR：衝突が見つかれば第二原像も見つかる
- SPR ⇒ OW：第二原像が見つかれば原像も見つかる
- 逆は成り立たない（反例が存在）

**具体的な攻撃例** ：
1. **MD5の衝突攻撃** ：2004年に実用的な衝突攻撃が発見
2. **SHA-1の衝突攻撃** ：2017年に実用的な衝突攻撃が発見
3. **誕生日攻撃** ：理論的な下限を示す攻撃手法

## 1.3.4 安全性モデルの関係性と実用性

### 暗号における安全性の関係性

暗号の安全性定義には明確な階層関係が存在します。以下に主要な関係性を示します：

#### 1. 安全性の強さの順序

**攻撃モデルによる関係性** ：

$ \text {IND-COA} < \text{IND-KPA} < \text{IND-CPA} < \text{IND-CCA1} < \text{IND-CCA2} $

**安全性目標による関係性** ：

$$
\text{OW} < \text{IND} < \text{NM}
$$

#### 2. 重要な定理と証明

**定理1：IND-CCA2 ⇒ NM**
IND-CCA2安全な暗号スキームは自動的に非展性（NM）も満たします。

**証明の概要** ：
- 攻撃者が暗号文を改変して新しい暗号文を作成しようとする
- IND-CCA2では復号オラクルにアクセス可能
- 改変された暗号文を復号して元の平文との関係性を調べることができる
- しかし、IND-CCA2の定義により、このような攻撃は negligible な確率でしか成功しない

**定理2：IND-CPA ⇒ OW**
IND-CPA安全な暗号スキームは一方向性（OW）も満たします。

**証明の概要** ：
- 攻撃者が暗号文から平文を復元できたとする
- この攻撃者を使って2つの平文の暗号文を区別する攻撃を構成できる
- これはIND-CPAの定義に矛盾する

#### 3. 数学的な安全性の伝播

**安全性の合成定理** ：
暗号スキーム $\Pi$ が攻撃モデル $\mathcal{A}$ に対して安全性目標 $\mathcal{S}$ を満たす場合、より弱い攻撃モデル $\mathcal{A}'$ に対しても同じ安全性目標 $\mathcal{S}$ を満たします。

**例** ：
- IND-CCA2安全 ⇒ IND-CPA安全
- IND-CPA安全 ⇒ IND-KPA安全
- IND-KPA安全 ⇒ IND-COA安全

#### 4. 実用的な意味

**設計指針** ：
- 現代の暗号設計では、IND-CCA2安全性を目標とする
- これにより、OW、IND、NMのすべての安全性目標が自動的に達成される
- 攻撃者の能力を最大限に想定することで、実用的な安全性を保証

**注意点** ：
- 理論的な安全性と実装の安全性は別の問題
- パディングオラクル攻撃などの実装レベルの脆弱性に注意が必要
- 鍵管理や乱数生成の品質も安全性に大きく影響する

### 暗号における関係性
重要な事実として、 **IND-CCA2安全性を満たす暗号は自動的に非展性（NM）も満たす** ことが証明されています。このため、現代の暗号設計ではIND-CCA2を最重要目標として設計されています。

### 実用的な安全性要件
- **TLS/HTTPS** ：IND-CCA2安全な暗号 + EUF-CMA安全な署名 + CR安全なハッシュ関数
- **ディジタル証明書** ：EUF-CMA安全な署名 + CR安全なハッシュ関数
- **パスワード保存** ：OW安全なハッシュ関数（加塩）

これらのモデルにより、「現実的な攻撃に対して暗号が十分に強い」ことを理論的に保証できます。

## 1.4 暗号技術と計算困難性

現代暗号の安全性は、 **計算困難性** に基づいています。つまり、暗号を破るために必要な計算量が現実的な時間・資源では実行不可能なほど大きいことに依存します。

### 代表的な計算困難問題

#### 1. 素因数分解問題（RSA暗号の基盤）
大きな合成数を素因数に分解する問題です。
```
例：15 = 3 × 5（簡単）
しかし：2048ビットの合成数の分解は現在のコンピュータでは事実上不可能
```

#### 2. 離散対数問題（DH鍵交換、ElGamal暗号の基盤）
$ mod\ p $ での指数計算の逆算問題

例： $ 5^x ≡ 18\ (mod\ 23) $ の $x$ を求める問題
小さな数では解けるが、大きな素数では困難


### 安全性の直感的理解

鍵長と計算時間の関係を考えてみましょう：

- **56ビットDES** ：1997年に78時間で破られた
- **128ビットAES** ：現在のスーパーコンピュータでも宇宙の年齢より長い時間が必要
- **2048ビットRSA** ：現在の技術では安全だが、量子コンピュータが実用化されると危険

このように、暗号の安全性は「攻撃者の計算資源」と「暗号アルゴリズムの計算困難性」の競争とも言えます。

## 1.5 現実世界での応用例

理論的な暗号技術が実際にどのように使われているかを見てみましょう。

### 1. TLS/HTTPS：Web通信の保護

Webブラウザとサーバー間の通信では、複数の暗号技術が組み合わせて使われます：

```
1. ハンドシェイク段階：
   - RSA/ECDSA署名でサーバー認証
   - ECDH鍵交換で共通鍵を安全に共有

2. データ転送段階：
   - AES-GCMで高速な暗号化・復号
   - HMAC-SHA256で完全性確認
```

### 2. Git：バージョン管理システムでの完全性確認

Gitでは、すべてのコミット・ファイル・ディレクトリがSHA-1ハッシュ値で管理されています：

```
コミット ---> SHA-1ハッシュ ---> コミットID
親コミット、ファイル内容、メッセージなどすべてがハッシュ値に反映
→ 改ざんすると即座に検知可能
```

### 3. クラウドストレージ：データの分散保存

大手クラウドサービスでは、ユーザーデータを複数の暗号技術で保護しています：

```
ユーザーデータ
└─ AES暗号化（機密性）
   └─ 秘密分散で複数拠点に保存（可用性）
      └─ ディジタル署名で完全性確認
```

これらの例からわかるように、現実のシステムでは複数の暗号技術を組み合わせて、機密性・完全性・認証・否認防止の4つの目的を同時に達成しています。
