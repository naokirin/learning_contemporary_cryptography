# 第3回　ハッシュ関数とメッセージ認証コード（MAC）

## はじめに

前回は共通鍵暗号と暗号モードについて学びました。今回は、データの完全性と認証を保証する重要な技術である**ハッシュ関数**と**メッセージ認証コード（MAC）**について詳しく見ていきます。

これらの技術は、暗号化とは異なる目的を持っています。暗号化が「機密性」を提供するのに対し、ハッシュ関数とMACは「完全性」と「認証」を提供します。つまり、データが改ざんされていないことを確認し、正しい送信者からのものであることを保証する技術です。

## 3.1 ハッシュ関数の概要

### ハッシュ関数とは

**ハッシュ関数**は、任意長の入力データを固定長の「指紋（ダイジェスト）」に変換する関数です。数学的には以下のように表現されます：

$$H: \{0,1\}^* \rightarrow \{0,1\}^n$$

ここで、$\{0,1\}^*$は任意長のビット列、$\{0,1\}^n$は$n$ビットの固定長ビット列を表します。

### ハッシュ関数の基本動作

```
データ(M) ---> [ハッシュ関数H] ---> ダイジェスト(H(M))
```

例えば、メッセージ$M$に対してハッシュ関数$H$を適用すると、固定長のダイジェスト$H(M)$が得られます。

### ハッシュ関数の特徴

ハッシュ関数には以下の重要な特徴があります：

1. **一方向性（One-way）**
   - 与えられたダイジェストから元のデータを求めるのは計算的に困難
   - 数学的には、$H(M)$から$M$を求める逆関数が存在しない

2. **衝突耐性（Collision Resistance）**
   - 異なる入力が同じ出力になる確率が極めて低い
   - 数学的には、$M_1 \neq M_2$かつ$H(M_1) = H(M_2)$となる$M_1, M_2$を見つけるのが困難

3. **雪崩効果（Avalanche Effect）**
   - 入力の小さな変更が出力に大きな変化をもたらす
   - 1ビットの変更でも出力の約50%のビットが変化する

### ハッシュ関数の用途

ハッシュ関数は以下のような場面で利用されます：

- **データ完全性の確認**：ファイルの改ざん検出
- **デジタル署名の前処理**：長いメッセージを短いダイジェストに変換
- **パスワードの安全な保存**：平文パスワードをハッシュ値として保存
- **データベースのインデックス**：効率的な検索のためのハッシュテーブル

## 3.2 ハッシュ関数の安全性

### 安全性の定義

ハッシュ関数の安全性は、以下の3つの概念で定義されます：

#### 1. 原像困難性（Preimage Resistance）

**定義**：与えられたハッシュ値$y$に対して、$H(x) = y$となる$x$を見つけるのが困難

数学的には、任意の$y \in \{0,1\}^n$に対して、$H(x) = y$となる$x$を求めるのが計算量的に困難であることを意味します。

#### 2. 第二原像困難性（Second Preimage Resistance）

**定義**：特定の入力$x_1$に対して、$H(x_1) = H(x_2)$となる別の入力$x_2 \neq x_1$を見つけるのが困難

これは、既知のメッセージと同じハッシュ値を持つ別のメッセージを見つける攻撃に対する耐性です。

#### 3. 衝突耐性（Collision Resistance）

**定義**：任意の2つの異なる入力$x_1, x_2$に対して、$H(x_1) = H(x_2)$となるペアを見つけるのが困難

これは最も強力な安全性概念で、任意の2つのメッセージの衝突を見つける攻撃に対する耐性です。

### 安全性の関係

これらの安全性概念には以下の関係があります：

```
衝突耐性 → 第二原像困難性 → 原像困難性
```

つまり、衝突耐性が最も強く、原像困難性が最も弱い概念です。

### 攻撃の計算量

理想的なハッシュ関数に対する攻撃の計算量は以下の通りです：

- **原像攻撃**：$O(2^n)$（総当たり攻撃）
- **第二原像攻撃**：$O(2^n)$（総当たり攻撃）
- **衝突攻撃**：$O(2^{n/2})$（誕生日攻撃）

ここで$n$はハッシュ値のビット長です。衝突攻撃が最も効率的なのは、誕生日攻撃と呼ばれる確率的な手法が存在するためです。

### 誕生日攻撃（Birthday Attack）

誕生日攻撃は、誕生日のパラドックスに基づく確率的な攻撃手法です。

#### 誕生日のパラドックス

23人のグループの中に同じ誕生日の人がいる確率は約50%です。これは直感に反する結果ですが、確率論的に説明できます。

**数学的説明**：
- $n$人のグループで全員が異なる誕生日である確率：$P(n) = \frac{365!}{(365-n)! \cdot 365^n}$
- 少なくとも2人が同じ誕生日である確率：$1 - P(n)$
- $n = 23$のとき、この確率は約50.7%

#### ハッシュ関数への応用

ハッシュ関数の衝突攻撃では、$2^n$個の可能なハッシュ値の中から衝突を見つける問題です。

**攻撃手法**：
1. ランダムなメッセージ$M_1, M_2, \ldots, M_k$を生成
2. 各メッセージのハッシュ値$H(M_1), H(M_2), \ldots, H(M_k)$を計算
3. ハッシュ値の衝突を探す

**計算量の導出**：
- $k$個のハッシュ値が全て異なる確率：$P(k) = \frac{2^n!}{(2^n-k)! \cdot (2^n)^k}$
- 衝突が存在する確率：$1 - P(k)$
- $k \approx \sqrt{2^n} = 2^{n/2}$のとき、衝突の確率が約50%

#### 具体的な例

**128ビットハッシュ関数（MD5）**：
- 総当たり攻撃：$2^{128}$回の計算
- 誕生日攻撃：約$2^{64}$回の計算
- 効率化：$2^{64}$倍の高速化

**256ビットハッシュ関数（SHA-256）**：
- 総当たり攻撃：$2^{256}$回の計算
- 誕生日攻撃：約$2^{128}$回の計算
- 効率化：$2^{128}$倍の高速化

#### 実装上の考慮事項

誕生日攻撃を実装する際の重要なポイント：

1. **メモリ使用量**：$2^{n/2}$個のハッシュ値を保存する必要がある
2. **並列処理**：複数のプロセッサで並列に計算可能
3. **確率的性質**：必ずしも衝突が見つかるとは限らない

この攻撃手法により、ハッシュ関数の出力長は衝突攻撃に対して十分な長さである必要があります。現在では、少なくとも256ビットの出力長が推奨されています。

### 脆弱なハッシュ関数の例

#### MD5（Message Digest Algorithm 5）

- 出力長：128ビット
- 1991年に設計され、広く使用された
- 2004年に衝突攻撃が発見され、現在は安全ではない
- 計算量：約$2^{20}$で衝突を発見可能

#### SHA-1（Secure Hash Algorithm 1）

- 出力長：160ビット
- 1995年に設計され、MD5の後継として使用された
- 2017年に実用的な衝突攻撃が発見され、現在は推奨されない
- 計算量：約$2^{63}$で衝突を発見可能

これらの脆弱性は、暗号学的ハッシュ関数の設計における重要な教訓となっています。

## 3.3 ハッシュ関数の種類

### 古典的ハッシュ関数

#### MD4（Message Digest Algorithm 4）

- 設計者：Ronald Rivest（1990年）
- 出力長：128ビット
- ブロック長：512ビット
- 現在の状況：完全に破られている

**歴史的経緯**：
MD4は、RSA暗号の共同開発者であるRonald Rivestによって1990年に設計されました。当時、デジタル署名の前処理として使用する高速なハッシュ関数が必要とされていました。MD4は、それまでのハッシュ関数よりも高速で実装が簡単な設計として注目されましたが、1995年にDobbertinにより衝突攻撃が発見され、安全性が疑問視されるようになりました。

**アルゴリズム概要**：
MD4は3ラウンドの圧縮関数を使用するMerkle-Damgård構造を採用しています。

1. **パディング**：メッセージ長を512ビットの倍数にする
2. **初期化**：4つの32ビットレジスタ（A, B, C, D）を初期値で初期化
3. **圧縮関数**：512ビットブロックごとに3ラウンドの処理を実行
   - ラウンド1：非線形関数F(x,y,z) = (x ∧ y) ∨ (¬x ∧ z)
   - ラウンド2：非線形関数G(x,y,z) = (x ∧ y) ∨ (x ∧ z) ∨ (y ∧ z)
   - ラウンド3：非線形関数H(x,y,z) = x ⊕ y ⊕ z
4. **出力**：最終的なA, B, C, Dの連結が128ビットハッシュ値

#### MD5（Message Digest Algorithm 5）

- 設計者：Ronald Rivest（1991年）
- 出力長：128ビット
- ブロック長：512ビット
- 現在の状況：衝突攻撃により安全ではない

**歴史的経緯**：
MD5は、MD4の脆弱性を受けて、Ronald Rivestによって1991年に設計されました。MD4の安全性問題を解決するため、より強固な設計として4ラウンドの圧縮関数を採用し、より複雑なパディング方式を導入しました。MD5は1990年代から2000年代にかけて広く使用され、ファイルの完全性確認やデジタル署名の前処理として標準的なハッシュ関数となりました。しかし、2004年にWangらにより実用的な衝突攻撃が発見され、現在は安全ではないとされています。

**アルゴリズム概要**：
MD5はMD4を改良した4ラウンドの圧縮関数を使用するMerkle-Damgård構造です。

1. **パディング**：メッセージ長を512ビットの倍数にする（1ビットの1、0ビット、64ビットの長さ）
2. **初期化**：4つの32ビットレジスタ（A, B, C, D）を固定値で初期化
3. **圧縮関数**：512ビットブロックごとに4ラウンドの処理を実行
   - ラウンド1：F(x,y,z) = (x ∧ y) ∨ (¬x ∧ z)
   - ラウンド2：G(x,y,z) = (x ∧ z) ∨ (y ∧ ¬z)
   - ラウンド3：H(x,y,z) = x ⊕ y ⊕ z
   - ラウンド4：I(x,y,z) = y ⊕ (x ∨ ¬z)
4. **出力**：最終的なA, B, C, Dの連結が128ビットハッシュ値

**脆弱性**：2004年にWangらにより衝突攻撃が発見され、約$2^{20}$の計算量で衝突を発見可能

### 現代的ハッシュ関数

#### SHA-1（Secure Hash Algorithm 1）

- 設計者：NSA（1995年）
- 出力長：160ビット
- ブロック長：512ビット
- 現在の状況：衝突攻撃により推奨されない

**歴史的経緯**：
SHA-1は、アメリカ国家安全保障局（NSA）によって1995年に設計され、連邦情報処理標準（FIPS）として制定されました。MD5の安全性問題を受けて、より安全なハッシュ関数として160ビットの出力長を採用し、SHA-0の改良版として開発されました。SHA-1は政府機関や金融機関で広く採用され、SSL/TLS、SSH、Gitなど多くのシステムで使用されました。しかし、2005年に理論的な脆弱性が発見され、2017年にGoogleにより実用的な衝突攻撃が実証され、現在は推奨されていません。

**アルゴリズム概要**：
SHA-1は5つの32ビットレジスタを使用するMerkle-Damgård構造です。

1. **パディング**：メッセージ長を512ビットの倍数にする
2. **初期化**：5つの32ビットレジスタ（A, B, C, D, E）を固定値で初期化
3. **圧縮関数**：512ビットブロックごとに80ラウンドの処理を実行
   - ラウンド1-20：F(x,y,z) = (x ∧ y) ∨ (¬x ∧ z)
   - ラウンド21-40：F(x,y,z) = x ⊕ y ⊕ z
   - ラウンド41-60：F(x,y,z) = (x ∧ y) ∨ (x ∧ z) ∨ (y ∧ z)
   - ラウンド61-80：F(x,y,z) = x ⊕ y ⊕ z
4. **出力**：最終的なA, B, C, D, Eの連結が160ビットハッシュ値

**脆弱性**：2017年にGoogleにより実用的な衝突攻撃が実証され、約$2^{63}$の計算量で衝突を発見可能

#### SHA-2ファミリー

SHA-2は以下のバリエーションがあります：

- **SHA-224**：出力長224ビット
- **SHA-256**：出力長256ビット
- **SHA-384**：出力長384ビット
- **SHA-512**：出力長512ビット
- **SHA-512/224**：出力長224ビット
- **SHA-512/256**：出力長256ビット

**歴史的経緯**：
SHA-2ファミリーは、NSAによって2001年に設計され、2002年にFIPS 180-2として標準化されました。SHA-1の理論的脆弱性を受けて、より長い出力長（224ビット、256ビット、384ビット、512ビット）を提供するハッシュ関数ファミリーとして開発されました。SHA-2は、SHA-1と同様のMerkle-Damgård構造を採用しながら、より強固な設計を実現しています。現在、SHA-256とSHA-512が最も広く使用されており、SSL/TLS、Bitcoin、多くのセキュリティプロトコルで標準的なハッシュ関数として採用されています。

SHA-2の構造は以下のようになります：

```
データ ---> パディング ---> ブロック分割 ---> ハッシュ計算 ---> 出力
```

**アルゴリズム概要**：
SHA-2ファミリーはMerkle-Damgård構造を採用し、SHA-256とSHA-512で異なるワードサイズを使用します。

**SHA-256**：
1. **パディング**：メッセージ長を512ビットの倍数にする
2. **初期化**：8つの32ビットレジスタ（A, B, C, D, E, F, G, H）を固定値で初期化
3. **圧縮関数**：512ビットブロックごとに64ラウンドの処理を実行
   - メッセージスケジュール：16個の32ビットワードを64個に拡張
   - 主要関数：Ch(x,y,z) = (x ∧ y) ⊕ (¬x ∧ z)、Maj(x,y,z) = (x ∧ y) ⊕ (x ∧ z) ⊕ (y ∧ z)
   - 補助関数：Σ₀(x)、Σ₁(x)、σ₀(x)、σ₁(x)
4. **出力**：最終的なA, B, C, D, E, F, G, Hの連結が256ビットハッシュ値

**SHA-512**：
1. **パディング**：メッセージ長を1024ビットの倍数にする
2. **初期化**：8つの64ビットレジスタ（A, B, C, D, E, F, G, H）を固定値で初期化
3. **圧縮関数**：1024ビットブロックごとに80ラウンドの処理を実行
   - メッセージスケジュール：16個の64ビットワードを80個に拡張
   - 主要関数：Ch(x,y,z)、Maj(x,y,z)（SHA-256と同様）
   - 補助関数：Σ₀(x)、Σ₁(x)、σ₀(x)、σ₁(x)（64ビット版）
4. **出力**：最終的なA, B, C, D, E, F, G, Hの連結が512ビットハッシュ値

#### SHA-3ファミリー

SHA-3はKeccakをベースとした新しいハッシュ関数ファミリーです：

- **SHA3-224**：出力長224ビット
- **SHA3-256**：出力長256ビット
- **SHA3-384**：出力長384ビット
- **SHA3-512**：出力長512ビット

**歴史的経緯**：
SHA-3は、NIST（アメリカ国立標準技術研究所）が2007年に開始したSHA-3コンペティションの結果として選定されました。SHA-2に対する理論的攻撃の可能性を考慮し、異なる数学的構造を持つハッシュ関数を求めて国際的なコンペティションが開催されました。2012年にKeccakが最終候補として選定され、2015年にFIPS 202として標準化されました。SHA-3は、SHA-2とは異なるスポンジ構造を採用しており、理論的な安全性の向上と、SHA-2に対する代替手段としての役割を果たしています。現在、SHA-3は段階的に導入が進められており、特に高セキュリティ要件のシステムで採用されています。

**アルゴリズム概要**：
SHA-3はKeccakをベースとしたスポンジ構造を採用しています。

**スポンジ構造**：
1. **吸収フェーズ（Absorption）**：メッセージを内部状態に吸収
2. **絞り出しフェーズ（Squeezing）**：内部状態からハッシュ値を出力

**Keccak-f[1600]**：
1. **初期化**：1600ビットの内部状態を0で初期化
2. **パディング**：10*1パディング（末尾に1、中間に0、最後に1）
3. **吸収フェーズ**：メッセージブロックを内部状態にXOR
4. **置換関数**：24ラウンドのKeccak-f[1600]を適用
   - θ（Theta）：列パリティの計算
   - ρ（Rho）：ビット位置の回転
   - π（Pi）：レーンの置換
   - χ（Chi）：非線形変換
   - ι（Iota）：ラウンド定数のXOR
5. **絞り出しフェーズ**：必要な長さまで内部状態から出力

**バリエーション**：
- **SHA3-224**：出力長224ビット、容量448ビット
- **SHA3-256**：出力長256ビット、容量512ビット
- **SHA3-384**：出力長384ビット、容量768ビット
- **SHA3-512**：出力長512ビット、容量1024ビット

| ハッシュ関数 | 出力長    | ブロック長 | 安全性       | 推奨度   |

| MD5          | 128ビット | 512ビット  | 破られている | 使用禁止 |
| SHA-1        | 160ビット | 512ビット  | 脆弱         | 使用禁止 |
| SHA-256      | 256ビット | 512ビット  | 安全         | 推奨     |

## 3.4 メッセージ認証コード（MAC）の概要

### MACとは

**メッセージ認証コード（Message Authentication Code, MAC）**は、メッセージが改ざんされていないことを確認するための短いタグです。MACは以下の特徴を持ちます：

1. **共通鍵を使用**：送信者と受信者が同じ秘密鍵を共有
2. **データ完全性と認証を同時に提供**：改ざん検出と送信者認証
3. **短いタグ**：元のメッセージより短い固定長の出力

### MACの基本動作

```
データ(M) + 共通鍵(K) ---> [MAC関数] ---> MAC(M, K)
```

数学的には、MAC関数は以下のように定義されます：

$$MAC: \mathcal{K} \times \mathcal{M} \rightarrow \mathcal{T}$$

ここで、$\mathcal{K}$は鍵空間、$\mathcal{M}$はメッセージ空間、$\mathcal{T}$はタグ空間です。

### MACの生成と検証

#### MAC生成
1. メッセージ$M$と共通鍵$K$を入力
2. MAC関数を適用してタグ$T = MAC(K, M)$を生成
3. メッセージとタグの組$(M, T)$を送信

#### MAC検証
1. 受信したメッセージ$M'$とタグ$T'$を取得
2. 共通鍵$K$を使用して$T = MAC(K, M')$を計算
3. $T = T'$ならば検証成功、そうでなければ検証失敗

### MACの性質

MACは以下の重要な性質を持ちます：

1. **偽造困難性**：攻撃者は有効なMACを生成できない
2. **鍵依存性**：異なる鍵では異なるMACが生成される
3. **一意性**：同じメッセージでも異なる鍵では異なるMACが生成される

## 3.5 MACの安全性

### 安全性の定義

MACの安全性は**偽造困難性（Unforgeability）**で定義されます：

**定義**：攻撃者は、過去にMACを計算したメッセージ以外のメッセージに対して有効なMACを生成できない

### 攻撃モデル

MACに対する攻撃モデルとして、**選択メッセージ攻撃（Chosen Message Attack, CMA）**が考えられます：

1. 攻撃者は任意のメッセージ$M_i$を選択
2. オラクルが$MAC(K, M_i)$を返す
3. 攻撃者は新しいメッセージ$M^*$とタグ$T^*$を出力
4. $M^*$が過去にクエリしたメッセージでなく、$T^* = MAC(K, M^*)$なら攻撃成功

### MACの安全性の基盤

MACの安全性は、基盤となる暗号技術の安全性に依存します：

1. **ブロック暗号ベースMAC**：基盤となるブロック暗号の安全性
2. **ハッシュ関数ベースMAC**：基盤となるハッシュ関数の安全性

### 攻撃例

#### 長さ拡張攻撃（Length Extension Attack）

単純なハッシュ関数ベースMACに対する攻撃：

```
MAC(K, M) = H(K || M)
```

この場合、攻撃者は$H(K || M)$から$H(K || M || M')$を計算できる可能性があります。

#### 鍵回復攻撃

弱い鍵を使用した場合の攻撃：

```
MAC(K, M) = H(K ⊕ M)
```

この場合、$K$が短い場合、総当たり攻撃で鍵を回復できる可能性があります。

## 3.6 MACの種類

### ブロック暗号ベースMAC

#### EMAC（Encrypted MAC）

EMACは最も単純なブロック暗号ベースMACです：

```
EMAC(K, M) = E_K(H(M))
```

ここで、$E_K$はブロック暗号の暗号化関数、$H$はハッシュ関数です。

**特徴**：
- シンプルな構造
- 基盤となるハッシュ関数の安全性に依存
- 長さ拡張攻撃に対して脆弱な場合がある

#### CMAC（Cipher-based MAC）

CMACはAESなどのブロック暗号ベースで安全性が向上したMACです：

```
CMAC(K, M) = CBC-MAC(K, M) ⊕ K_1 または K_2
```

**特徴**：
- CBC-MACの安全性問題を解決
- 可変長メッセージに対応
- AESなどの標準ブロック暗号と組み合わせて使用

### ハッシュ関数ベースMAC

#### HMAC（Hash-based MAC）

HMACは最も広く使用されているハッシュ関数ベースMACです：

```
HMAC(K, M) = H(K ⊕ opad || H(K ⊕ ipad || M))
```

ここで、$ipad$と$opad$は定数パターンです。

**構造**：
```
K ⊕ ipad ---> H ---> K ⊕ opad ---> H ---> HMAC
```

**特徴**：
- 任意のハッシュ関数と組み合わせ可能
- 長さ拡張攻撃に対して安全
- 理論的な安全性が証明されている

### MACの比較

| MAC  | 基盤技術     | 安全性 | 性能 | 用途             |
| ---- | ------------ | ------ | ---- | ---------------- |
| EMAC | ブロック暗号 | 中     | 高   | レガシーシステム |
| CMAC | ブロック暗号 | 高     | 高   | AES環境          |
| HMAC | ハッシュ関数 | 高     | 中   | 汎用             |

## 3.7 現実世界での応用例

### TLSにおけるMAC

TLS（Transport Layer Security）では、データの完全性と認証を保証するためにMACが使用されます。

#### TLS 1.2でのMAC

```
データ ---> 暗号化 ---> MACタグ
```

TLS 1.2では以下のMACが使用されます：

- **HMAC-SHA256**：最も一般的
- **HMAC-SHA384**：高セキュリティ要件
- **HMAC-SHA1**：レガシーサポート（非推奨）

#### TLS 1.3での変更

TLS 1.3では、MACの代わりに**認証付き暗号（AEAD）**が使用されます：

- **AES-GCM**：認証と暗号化を同時に提供
- **ChaCha20-Poly1305**：高速なAEAD

### Gitにおけるハッシュ関数

Gitでは、データの完全性確認のためにSHA-1ハッシュ関数が使用されています。

#### コミットハッシュ

```
コミット内容 ---> SHA-1 ---> コミットハッシュ
```

各コミットには一意のハッシュ値が割り当てられ、以下の情報が含まれます：

- コミットメッセージ
- 親コミットのハッシュ
- ファイルツリーのハッシュ
- タイムスタンプ

#### コミットチェーン

```
コミット1 ---> コミット2 ---> コミット3
SHA-1_1      SHA-1_2      SHA-1_3
```

この構造により、過去のコミットを改ざんすると、後続のすべてのコミットハッシュが変化するため、改ざんが検出されます。

### ファイル署名

ソフトウェア配布では、ファイルの完全性を確認するためにハッシュ関数が使用されます。

#### 例：Linuxディストリビューション

```
Ubuntu-22.04.iso ---> SHA-256 ---> ハッシュ値
```

配布サイトでは、ISOファイルとともにSHA-256ハッシュ値が提供され、ダウンロード後にハッシュ値を計算して比較することで、ファイルの完全性を確認できます。

### クラウドストレージでのデータ検証

クラウドストレージサービスでは、データの完全性を保証するためにハッシュ関数が使用されます。

#### 例：AWS S3

S3では、アップロード時にContent-MD5ヘッダーを使用してデータの完全性を確認します：

```
ファイル ---> MD5 ---> Content-MD5ヘッダー
```

ただし、MD5は現在安全ではないため、より安全なハッシュ関数の使用が推奨されています。

## 3.8 まとめと次回へのつなぎ

### 第3回の要点

今回学んだハッシュ関数とメッセージ認証コード（MAC）について、重要なポイントを整理します：

#### ハッシュ関数
- **目的**：データの完全性確認、デジタル署名の前処理
- **安全性**：原像困難性、第二原像困難性、衝突耐性
- **種類**：MD5/SHA-1（脆弱）、SHA-2/SHA-3（安全）

#### メッセージ認証コード（MAC）
- **目的**：データ完全性と認証の同時提供
- **安全性**：偽造困難性
- **種類**：EMAC、CMAC、HMAC

### 暗号技術における位置づけ

ハッシュ関数とMACは、現代暗号技術において以下の役割を果たします：

```
機密性：共通鍵暗号・公開鍵暗号
完全性：ハッシュ関数・MAC
認証：MAC・デジタル署名
否認防止：デジタル署名
```

### 次回予告

次回（第4回）では、**RSA暗号・分散署名・準同型暗号**について学びます。

#### 扱うトピック
- **RSA暗号**：素因数分解の困難性に基づく公開鍵暗号
- **RSA署名**：デジタル署名の実現
- **分散署名**：秘密鍵の安全な分散管理
- **準同型暗号**：暗号化したまま計算を実行

#### 応用例
- 電子証明書（X.509）とTLSハンドシェイク
- ソフトウェア配布の署名
- 分散署名による秘密鍵の安全な管理
- 電子投票・アンケートシステム

公開鍵暗号と署名、そしてその応用技術まで、より高度な暗号技術について詳しく見ていきましょう。
