# 第6回　高機能暗号とその応用

## はじめに

前回の第5回では、離散対数問題に基づく暗号技術について学びました。今回は、従来の暗号化・署名を超えて、特定の機能を暗号文上で実現する **高機能暗号（Advanced Cryptography / Functional Cryptography）** について解説します。

高機能暗号は、単純な暗号化や署名だけでなく、暗号化されたデータに対して検索や計算、アクセス制御などの高度な操作を可能にする暗号技術です。これにより、プライバシーを保ちながら、より柔軟で実用的な暗号システムを構築できます。

## 6.1 高機能暗号とは

### 高機能暗号の概要

**高機能暗号** は、従来の暗号技術が提供する機密性・完全性・認証に加えて、暗号文上で特定の機能を実行できる暗号方式の総称です。

従来の暗号では、データを暗号化すると、復号するまでそのデータに対して何も操作できませんでした。しかし、高機能暗号では、暗号化された状態で以下のような操作が可能になります：

- **検索可能暗号**: 暗号文のままキーワード検索を実行
- **属性ベース暗号**: ユーザーの属性に基づいて復号権限を制御
- **準同型暗号**: 暗号文上で計算を実行
- **グループ署名・リング署名**: 匿名性を保ちながら署名を生成

### 高機能暗号の分類

高機能暗号は、その機能によって以下のように分類できます：

```
高機能暗号
├─ 属性ベース暗号（ABE）
│  ├─ KP-ABE（Key-Policy ABE）
│  └─ CP-ABE（Ciphertext-Policy ABE）
├─ 検索可能暗号（SE）
│  ├─ 対称検索可能暗号（SSE）
│  └─ 非対称検索可能暗号（ASE）
├─ 準同型暗号（HE）
│  ├─ 部分準同型暗号
│  └─ 完全準同型暗号（FHE）
├─ グループ署名
└─ リング署名
```

### 理論的な背景

高機能暗号の実現には、以下の数学的構造が重要な役割を果たします：

1. **双線型ペアリング**: 楕円曲線上の特殊な写像
2. **格子暗号**: 格子問題の困難性に基づく暗号
3. **多変数多項式**: 多変数連立方程式の求解困難性
4. **符号暗号**: 誤り訂正符号の理論を応用

これらの数学的構造により、従来の暗号では実現できなかった高度な機能が可能になります。

## 6.2 属性ベース暗号（ABE: Attribute-Based Encryption）

### 属性ベース暗号の概要

**属性ベース暗号（ABE）** は、ユーザーの属性（役職、部署、権限など）に基づいて暗号化・復号を制御する暗号方式です。従来の公開鍵暗号では、特定の受信者に対してのみ暗号化できましたが、ABEでは属性の組み合わせによって柔軟なアクセス制御が可能です。

### 基本的な概念

**属性（Attribute）**
- ユーザーやデータに関連する特性
- 例：`role=manager`, `department=engineering`, `level=senior`

**アクセスポリシー（Access Policy）**
- 復号に必要な属性の条件
- 例：`(role=manager AND department=engineering) OR level=senior`

### ABEの種類

#### KP-ABE（Key-Policy ABE）

**KP-ABE** では、ユーザーの秘密鍵にアクセスポリシーが埋め込まれ、暗号文に属性が関連付けられます。

**アルゴリズム（KP-ABE）**

1. **システム設定**
   - マスター秘密鍵 $ \text{MSK} $ とシステムパラメータ $ \text{PP} $ を生成

2. **鍵生成**
   - アクセスポリシー $ \mathcal{P} $ とマスター秘密鍵から秘密鍵 $ \text{SK}_{\mathcal{P}} $ を生成

3. **暗号化**
   - 属性集合 $ S $ と平文 $ M $ から暗号文 $ \text{CT} = \text{Enc}(\text{PP}, S, M) $ を生成

4. **復号**
   - 属性集合 $ S $ がアクセスポリシー $ \mathcal{P} $ を満たす場合のみ復号可能

#### CP-ABE（Ciphertext-Policy ABE）

**CP-ABE** では、暗号文にアクセスポリシーが埋め込まれ、ユーザーの秘密鍵に属性が関連付けられます。

**アルゴリズム（CP-ABE）**

1. **システム設定**
   - マスター秘密鍵 $ \text{MSK} $ とシステムパラメータ $ \text{PP} $ を生成

2. **鍵生成**
   - 属性集合 $ S $ とマスター秘密鍵から秘密鍵 $ \text{SK}_S $ を生成

3. **暗号化**
   - アクセスポリシー $ \mathcal{P} $ と平文 $ M $ から暗号文 $ \text{CT} = \text{Enc}(\text{PP}, \mathcal{P}, M) $ を生成

4. **復号**
   - ユーザーの属性集合 $ S $ がアクセスポリシー $ \mathcal{P} $ を満たす場合のみ復号可能

### 双線型ペアリングの活用

ABEの実現には、**双線型ペアリング** が重要な役割を果たします。

**双線型ペアリングの定義**
- 群 $ G_1, G_2, G_T $ と写像 $ e: G_1 \times G_2 \rightarrow G_T $
- 双線型性：$ e(aP, bQ) = e(P, Q)^{ab} $
- 非退化性：$ e(P, Q) \neq 1 $ （単位元でない）

この性質により、属性とポリシーの組み合わせに基づく復号制御が実現されます。

### 応用例：クラウドデータのアクセス制御

**企業での機密文書管理**
```
文書の暗号化ポリシー：
(role=manager AND department=engineering) OR 
(role=director AND level=senior)

ユーザーA（role=manager, department=engineering）→ 復号可能
ユーザーB（role=director, level=senior）→ 復号可能
ユーザーC（role=staff, department=marketing）→ 復号不可
```

**医療データのアクセス制御**
```
患者データの暗号化ポリシー：
(role=doctor AND specialty=cardiology) OR
(role=nurse AND ward=ICU)

主治医（role=doctor, specialty=cardiology）→ 復号可能
ICU看護師（role=nurse, ward=ICU）→ 復号可能
一般看護師（role=nurse, ward=general）→ 復号不可
```

## 6.3 検索可能暗号（Searchable Encryption）

### 検索可能暗号の概要

**検索可能暗号（SE）** は、暗号化されたデータに対して検索を実行できる暗号方式です。クラウドストレージにデータを暗号化して保存しながら、必要なデータを効率的に検索できるため、プライバシー保護と利便性を両立できます。

### 検索可能暗号の種類

#### 対称検索可能暗号（SSE）

**SSE** では、データ所有者が同じ秘密鍵で暗号化と検索を行います。

**アルゴリズム（SSE）**

1. **データ暗号化**
   - 文書集合 $ D = \{d_1, d_2, \ldots, d_n\} $ を暗号化
   - 各文書 $ d_i $ からキーワード集合 $ W_i $ を抽出
   - 暗号化文書 $ C_i = \text{Enc}(K, d_i) $ を生成

2. **インデックス構築**
   - キーワード $ w $ に対して、そのキーワードを含む文書IDの暗号化リストを生成
   - インデックス $ I_w = \text{Enc}(K, \{i : w \in W_i\}) $

3. **検索トークン生成**
   - 検索キーワード $ w $ から検索トークン $ \tau_w = \text{Token}(K, w) $ を生成

4. **検索実行**
   - 検索トークン $ \tau_w $ を使用してインデックス $ I_w $ から該当文書IDを取得
   - 該当する暗号化文書を返却

#### 非対称検索可能暗号（ASE）

**ASE** では、公開鍵で暗号化し、秘密鍵で検索トークンを生成します。

**アルゴリズム（ASE）**

1. **鍵生成**
   - 公開鍵 $ \text{PK} $ と秘密鍵 $ \text{SK} $ を生成

2. **データ暗号化**
   - 公開鍵 $ \text{PK} $ を使用して文書を暗号化
   - 暗号文 $ C = \text{Enc}(\text{PK}, d) $ を生成

3. **検索トークン生成**
   - 秘密鍵 $ \text{SK} $ と検索キーワード $ w $ から検索トークン $ \tau_w = \text{Token}(\text{SK}, w) $ を生成

4. **検索実行**
   - 検索トークン $ \tau_w $ を使用して暗号文から該当文書を検索

### 検索可能暗号の安全性

検索可能暗号では、以下の安全性要件が重要です：

1. **選択平文攻撃に対する安全性（IND-CPA）**
   - 暗号文から平文の内容を推測できない

2. **検索パターンの保護**
   - 同じキーワードの検索が同じトークンになることを防ぐ

3. **アクセスパターンの保護**
   - 検索結果から文書間の関係性を推測できない

### 応用例：クラウド上の暗号化検索

**クラウドストレージでの検索**
```
1. ユーザーが機密文書をクラウドに暗号化してアップロード
2. 検索したいキーワードから検索トークンを生成
3. クラウドプロバイダーが検索トークンを使用して暗号化データ内を検索
4. 該当する暗号化文書のみを返却
5. ユーザーがローカルで復号して結果を確認
```

**医療記録の安全な検索**
```
1. 患者の医療記録を暗号化して保存
2. 医師が必要な症状や検査結果で検索
3. 該当する患者の暗号化記録のみを取得
4. 医師が適切な権限で復号して診療に活用
```

## 6.4 グループ署名とリング署名

### グループ署名（Group Signature）

#### グループ署名の概要

**グループ署名** は、グループのメンバーのみが署名を生成でき、署名者はグループ内でのみ特定可能な署名方式です。グループ管理者が署名者の身元を開示する機能も提供されます。

#### グループ署名の性質

1. **匿名性**: 署名者はグループ内でのみ特定可能
2. **追跡可能性**: グループ管理者が署名者の身元を開示可能
3. **非連結性**: 同じ署名者の複数の署名を関連付けできない
4. **偽造困難性**: グループメンバー以外は署名を生成できない

#### グループ署名のアルゴリズム

**アルゴリズム（グループ署名）**

1. **システム設定**
   - グループ管理者がシステムパラメータを生成
   - グループ公開鍵 $ \text{GPK} $ とマスター秘密鍵 $ \text{GMK} $ を生成

2. **メンバー参加**
   - ユーザーがグループに参加申請
   - グループ管理者がメンバー秘密鍵 $ \text{GSK}_i $ を生成・配布

3. **署名生成**
   - メンバーがメッセージ $ m $ とメンバー秘密鍵 $ \text{GSK}_i $ から署名 $ \sigma = \text{Sign}(\text{GSK}_i, m) $ を生成

4. **署名検証**
   - 署名 $ \sigma $ とメッセージ $ m $ から署名の有効性を検証
   - 署名者がグループメンバーであることを確認

5. **署名者開示**
   - グループ管理者が署名 $ \sigma $ から署名者の身元を特定

### リング署名（Ring Signature）

#### リング署名の概要

**リング署名** は、署名者の集合（リング）のいずれかが署名を生成したことを証明するが、具体的な署名者は特定できない署名方式です。グループ署名と異なり、事前のグループ設定や管理者が不要です。

#### リング署名の性質

1. **匿名性**: 署名者がリング内の誰かであることは分かるが、具体的な署名者は特定不可能
2. **自発性**: 事前のグループ設定が不要
3. **非連結性**: 同じ署名者の複数の署名を関連付けできない
4. **偽造困難性**: リングメンバー以外は署名を生成できない

#### リング署名のアルゴリズム

**アルゴリズム（リング署名）**

1. **署名生成**
   - メッセージ $ m $、署名者の秘密鍵 $ \text{SK}_s $、リングメンバーの公開鍵集合 $ \{\text{PK}_1, \text{PK}_2, \ldots, \text{PK}_n\} $ から署名 $ \sigma = \text{Sign}(\text{SK}_s, m, \{\text{PK}_1, \ldots, \text{PK}_n\}) $ を生成

2. **署名検証**
   - 署名 $ \sigma $、メッセージ $ m $、リングメンバーの公開鍵集合から署名の有効性を検証
   - 署名者がリングメンバーのいずれかであることを確認

### 応用例

#### 電子投票システム

**グループ署名による電子投票**
```
1. 有権者が投票用紙にグループ署名を生成
2. 投票用紙は有権者であることを証明するが、具体的な有権者は匿名
3. 不正投票の場合は、選挙管理委員会が署名者の身元を開示可能
4. 投票結果の集計とプライバシー保護を両立
```

**リング署名による匿名投票**
```
1. 有権者が候補者選択にリング署名を生成
2. 有権者リストをリングとして使用
3. 投票内容は有権者であることを証明するが、具体的な有権者は特定不可能
4. 完全な匿名性を保ちながら投票の正当性を確保
```

#### 匿名での情報開示

**内部告発システム**
```
1. 告発者が告発内容にリング署名を生成
2. 告発者は組織のメンバーであることを証明するが、身元は匿名
3. 告発内容の信頼性を保ちながら、告発者の保護を実現
```

#### 暗号資産の匿名送金

**Moneroでのリング署名**
```
1. 送金者が取引にリング署名を生成
2. 過去の取引出力をリングとして使用
3. 送金者は過去の取引参加者であることを証明するが、具体的な送金者は特定不可能
4. 取引の追跡を困難にし、プライバシーを保護
```

## 6.6 高機能暗号の課題と展望

### 計算コストの課題

#### 性能上の制約

高機能暗号は、従来の暗号と比較して大幅に高い計算コストを必要とします：

**属性ベース暗号**
- 双線型ペアリングの計算が重い
- 属性数に比例して計算時間が増加
- 実用的な応用には最適化が必要

**検索可能暗号**
- インデックス構築に時間がかかる
- 検索時の計算コストが高い
- 大規模データセットでの性能が課題

**完全準同型暗号**
- 暗号文上の計算が非常に重い
- 実用的な応用にはまだ研究段階

#### 最適化技術

これらの課題に対して、以下の最適化技術が研究されています：

1. **ハードウェア加速**
   - GPU、FPGA、ASICを使用した高速化
   - 専用プロセッサの開発

2. **アルゴリズム最適化**
   - 効率的な実装手法の開発
   - 近似計算の活用

3. **ハイブリッド方式**
   - 高機能暗号と従来暗号の組み合わせ
   - 必要最小限の高機能暗号の使用

### 理論的基盤の課題

#### 双線型ペアリング

**現在の状況**
- 楕円曲線上での双線型ペアリングが実用化
- 特定の楕円曲線でのみ効率的に計算可能
- パラメータ選択の制約がある

**今後の課題**
- より効率的なペアリングの開発
- 汎用的な実装の標準化
- 安全性の理論的保証の強化

#### 格子暗号

**格子暗号の特徴**
- 量子計算機に対する耐性
- 高機能暗号の実現に有望
- 実装の複雑さが課題

**研究動向**
- NIST PQC標準化プロジェクトでの検討
- 実用的な実装の開発
- 安全性の理論的基盤の確立

### 実装と標準化の課題

#### 実装の複雑さ

**技術的課題**

## 6.7 まとめ

### 第6回の要点

今回の記事では、高機能暗号とその応用について学びました：

1. **高機能暗号の概要**: 従来の暗号を超えた高度な機能を提供
2. **属性ベース暗号**: ユーザー属性に基づく柔軟なアクセス制御
3. **検索可能暗号**: 暗号化データに対する検索機能
4. **グループ署名・リング署名**: 匿名性を保ちながらの署名機能
5. **実世界での応用**: クラウドストレージ、医療データ、電子投票など
6. **課題と展望**: 計算コスト、理論的基盤、実装の複雑さ

### 高機能暗号の重要性

高機能暗号は、現代のデジタル社会におけるプライバシー保護と利便性の両立を実現する重要な技術です：

**プライバシー保護**
- データの機密性を保ちながら高度な操作を可能
- ユーザーの匿名性を保護
- データ漏洩リスクの軽減

**利便性の向上**
- クラウドサービスでの安全なデータ活用
- 効率的な検索とアクセス制御
- 新しいサービスモデルの実現

### 暗号技術の進化

暗号技術は、単純な暗号化から始まり、認証、署名、そして高機能暗号へと進化してきました：

```
暗号技術の進化
├─ 古典暗号（シーザー暗号など）
├─ 現代暗号（共通鍵・公開鍵暗号）
├─ 認証・署名技術
├─ 高機能暗号
└─ 耐量子暗号（次回）
```

この進化により、デジタル社会におけるセキュリティとプライバシーの要求に応える技術が提供されています。

### 次回予告

次回の第7回では、**耐量子計算機暗号（Post-Quantum Cryptography）** について学びます。

量子コンピュータの登場により、現在広く使用されているRSA暗号や楕円曲線暗号が解読される可能性があります。次回は、量子コンピュータに強い暗号方式について解説し、NISTの標準化プロジェクトや実用的な格子暗号などについて取り上げます。

高機能暗号と耐量子暗号の組み合わせにより、将来のデジタル社会におけるセキュリティ基盤が構築されていくことでしょう。
